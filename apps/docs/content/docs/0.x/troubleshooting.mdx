---
title: Troubleshooting
description: Diagnose generation, rendering, validation, and submission problems.
---

## A component or prop is rejected during generation

Check the default-exported `createFieldwork` registration and the component's declared props. Keep literal component keys and statically inspectable registry objects. Broad `Record<string, ...>` annotations erase useful names. Unknown components, unknown props, missing required props, and incompatible prop values are errors.

If a wrapper or dynamic construction prevents static inspection, simplify the registration or provide a custom framework driver that returns a manifest.

## Generated enums are missing

Check the `enums` class names in `config/fieldwork.php`, the Composer PSR-4 mapping, and filesystem access. Run `fieldwork fields` to prepare enums before generating forms. Use class names or `null`, not closures. Clear cached Laravel config after changing mappings or discovery.

## A form renders but cannot submit

A bare definition supports local editing and validation. Bind it to a named driver, supply a callback descriptor, or provide a per-form executor or Effect operation. Check that the descriptor's `driver` matches the key in `createFieldwork({ submissions })` and that its binding has the format the driver expects.

For generated HTTP actions, the route must be named and its controller or closure parameters must reference a discovered FormRequest.

## Defaults change but the draft does not reset

Defaults initialize a mounted session. Rerendering does not discard edits. Use a React `key` when changing records, or call `form.reset(values)` deliberately. The precedence is explicit defaults, descriptor defaults, then definition defaults.

## Server errors appear in the wrong form

Configure the Inertia `errorBag` for forms sharing a page. Field errors use their canonical paths; root errors use the empty path. Errors from a submitted draft do not replace fields edited since that submission.

## A rule is not enforced in the browser

Generation reports constraints that cannot be represented on the client. Unique/existence queries, custom rules, closures, request-dependent conditions, and file content/size checks remain server responsibilities. Validation runs on submit, not on each edit or blur. See [validation](./validation.mdx).

## A nested write creates an object instead of an array

Use a schema, generated metadata, or initialized baseline that identifies the container shape. If the shape cannot be inspected, initialize the array through `append` or a whole-field update. Optional containers and dynamic indexes can return `undefined` when read.

## Cancellation does not undo a mutation

Cancellation interrupts local execution and suppresses stale results. A transport must honor the abort signal and release its own resources. The server may already have accepted the write; handle rollback or compensation in the application when required.

## CI reports generated drift

Run `fieldwork generate` locally, review the emitted definitions, actions, and obsolete files, and commit the result. The generator only synchronizes owned files bearing `// Generated by Fieldwork.` inside its configured output directories. Do not place unrelated generators in those same directories.

## Documentation generation fails

Run `pnpm docs:api` to isolate Refquill analysis from MDX rendering. All inputs must produce public declarations. Resolve TypeScript diagnostics and invalid metadata before rebuilding; failed generation preserves the previous JSON output. Use `pnpm docs:build` for the complete API, site, and Worker packaging pipeline.
